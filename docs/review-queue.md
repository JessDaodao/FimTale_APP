# 我的审核

“我的”页第二行的“我的审核”入口对所有登录用户开放，使用 `work/get_review_entries` 获取当前作者的作品审核记录。页面不再请求编辑角色权限、管理员队列或审核员信息，也不包含通过、退回、分配审核员操作。

保留与历史记录一致的悬浮页眉：16dp 外边距与圆角，滚动时固定并以 200ms 动画升至 4dp 阴影。审核记录使用填充卡片，状态与分组数量 Chip 无描边，不显示审核员姓名。

## 接口与分组

参考 `ft-front/app/pages/user/reviews.vue` 和 `ft-front/schema/openapi.json`。当前工作区中的 `ft-go` 尚未包含独立审核接口，因此以网页及其 OpenAPI 契约为准。审核记录状态为 0 待提交、1 审核中、2 已通过、3 已退回，不同于旧作品的 `status_review` 字段。

| 操作 | 接口 | 行为 |
| --- | --- | --- |
| 查看我的审核 | `GET work/get_review_entries` | 携带当前 Token，无分页或作者查询参数；所有权由服务端判定 |
| 提交、重新提交 | `POST work/submit_review` | 原生 MD3 弹窗确认后发送 JSON `work_id`，成功后刷新 |
| 查看作品 | 原生作品详情页 | 使用记录的 `work_id` |

记录按“可提交、审核中、等待重新提交、已完成”分组。待提交记录可能没有审核 ID，仍以 `work_id` 正常展示。退回后无重新提交限制，或已过 `resubmit_after`，允许重新提交；有未来限制时间时展示本地时间，到期后自动更新分组与按钮。无效时间不会误放行。已通过和审核中记录没有提交按钮。

沿用的 `ReviewQueueActivity` 内部类名保留已有页面引用。传入审核或作品 ID 时，仅在当前用户返回的列表中定位并以填充色突出对应记录，不改用管理员接口查找。

## 请求和生命周期

`ReviewQueueViewModel` 保留确认弹窗状态及正在执行的请求，重复点击或屏幕旋转不会重复提交。提交成功但刷新失败时，已提交作品仍在本地标记为审核中。响应丢失后先刷新核对结果，再允许重试。进程重建不会自动重放提交；切换账号、退出登录或收到 401 时清空旧记录并忽略过期响应。

`ReviewQueueTest` 使用本地接口模拟响应，验证普通用户入口、个人接口、四类状态、零审核 ID、重新提交限制、取消与确认、旋转、请求失败、账号切换和进程恢复。`ReviewQueueDeviceTest` 验证填充卡片、无描边 Chip、不展示审核员、悬浮页眉及深色主题的原生确认弹窗。测试不读取或修改真实审核记录。
